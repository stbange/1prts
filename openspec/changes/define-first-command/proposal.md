# Define the first command

## Why

An RTS commander can usually see the entire operation at a glance. In 1stprts, finding a good place to stand is itself a strategic choice. A small, timed port operation will show whether delegation and crew reports give the player enough information to make that choice well.

## What Changes

- Establish an embodied command interface, a scale and interior standard for every asset family, and a visual language for work in progress.
- Define *Tide Window*, a single-player mission with two viable investments, concurrent crew jobs, a rival claimant on a berth and a measurable outcome.
- Specify the C engine and editable Lua/content boundary, native and browser distribution, mobile touch and WebXR.
- Define unit coverage gates and executable mission acceptance criteria before implementation.

## Capabilities

### New Capabilities

- `field-command` covers the commander's viewpoint, crew orders and the information available in the field.
- `crewed-world` covers full-scale, staffed interiors and crossing between moving reference frames.
- `tide-window` covers the resource decision, berth contention and objective of the first mission.
- `runtime-content` covers external game content, script extensions and the accompanying licenses.
- `platform-play` covers the desktop, mobile web and immersive paths into the same game.
- `game-verification` covers the unit coverage gate and automated gameplay checks.

## Impact

This is the initial design proposal on an empty repository. The open tasks describe the first playable build. Aircraft, spacecraft and stations have scale and boarding criteria now, and their playable introductions follow the port mission. [Game concept](../../../docs/concept.md)
