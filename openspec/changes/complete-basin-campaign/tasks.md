# Orra Basin implementation checklist

Start with sections 1 and 2. Their first playable result is a commander aboard the **second** tank from a factory, able to identify and direct both crews while two haulers compete for the last load in a salvage lot. The depot and lift prototype can start as soon as world objects have stable identities. [Dependencies, roster and operation-by-operation acceptance](design.md)

## 1. Establish the simulation and test baseline

- [ ] 1.1 Capture the existing seven operation results, both Gate Six openings, the unopposed rival victory, both Tide Window landings, Long Watch pack overrides, 30/90 Hz checkpoints and the independent C, Lua and browser coverage reports. Record which observations require a real device or a person.
- [ ] 1.2 Give every runtime entity a stable instance ID, a separate catalog type ID, owner, crew, parent frame and status. Store crew orders, target references and reservations by instance ID. Adapt the existing scene rows and pack API v1 at load time. Exercise two identical hulls, an invalid target and a child whose parent moves.
- [ ] 1.3 Remove fixed scene, crew and order array limits that obstruct additional units. Grow collections together, validate content references before starting a mission, and fail an unaffordable allocation cleanly. Test a scene beyond the current 192-place limit and a failed spawn with its queue and ledger intact.
- [ ] 1.4 Extend the determinism checks to hash sorted instance IDs, positions in parent frames, crews, orders, contacts, stock and objective clocks. Give same-tick operations a stable sequence. Compare the headless and rendered results from the same normal inputs before converting the first mission.

## 2. Build multiple units and compete for material

- [ ] 2.1 Represent surveyed pads and physical salvage lots in Lua sector data. Keep enough reachable home plate for the two introductory build orders. Add a lot accessible to both armies. Resolve competing pickups once per load and show stock at the site, cargo aboard and processed alloy separately.
- [ ] 2.2 Replace the side-wide built flags with per-facility queues and per-pad reservations. Allow repeat orders at valid sites, staff each work bay and calculate the grid load and priority per facility. Handle duplicate confirmations, cancellation before and after work starts, blocked exits, staff reassignment and power restoration.
- [ ] 2.3 Spawn each completed unit with its own call sign, operators and hatch at the producing facility. Add first-person group selection and a place on the slate to inspect the queue, missing prerequisites and assigned crew. Show which factory and crew acknowledged the order.
- [ ] 2.4 Play the first delivery milestone. Commission the mill, produce two Lintels and a section, board the second vehicle, and give the two tanks different orders. Verify a four-alloy order placed with six free leaves two free, an occupied exit releases one tank once, and two opposing Moles arriving for the last load collect it only once. Repeat production with Compact Wakes.

## 3. Give battlefield orders and the rival tactical choices

- [ ] 3.1 Implement deterministic paths across authored roads, yards, rail lines, shallow and deep water, air approaches and docking lanes. Bind route permissions to the unit type. Reserve narrow crossings and berths, replan after an obstruction, and report unreachable targets on the slate. Units that share a destination must be able to arrive without occupying the same space.
- [ ] 3.2 Implement move, scout, escort, engage, hold, withdraw and support for the roles that can perform them. Attach escorts to moving targets. Preserve observer, last known position and report tick when a contact leaves sight. Make the chart, radio and opponent use that information. Exercise a changed route, a stale report, a canceled order and a group split.
- [ ] 3.3 Resolve fictional encounters using the units present, their orders, condition and terrain. Let a disabled crewed hull stay in the world with its occupants. Dispatch a Hinge or the appropriate recovery crew, tow or repair the hull, and restore the same instance. Connect specialist work to the world, including a Span opening a marked crossing and a Tally supporting the reported yard.
- [ ] 3.4 Replace the Compact's fixed build sequence with Lua decisions based on its own observations, supplies, staffed bays and objectives. Both commanders use the same order and cost rules. Replay different observed threats causing different responses, a stale-contact diversion, successful recovery, an idle-player loss, and a Gate Six claim interrupted at tick 1,799.

## 4. Finish the inhabited world

- [ ] 4.1 Define loose data for rooms, floors, solid machinery, entrances, connector type, crew stations, functional work areas and deck links. Use it for the visible mesh placement, collision and targeting. Exercise an open, closed, occupied and disconnected route. Reassign a station's only qualified worker and verify that its job waits while other crews continue. Restore the same progress after a handover or a room reload.
- [ ] 4.2 Build the reference walks first. Extend the Shore Depot to the concept's 65-metre length and fit the approach, working apron, dispatch office and gantry to it. Build a functioning Crown Station lift with a call control, landing doors and a traffic-control stop. Preserve the first-person body while the lift, ferry or tender moves.
- [ ] 4.3 Work through the roster batches in the design. Give each of the 61 craft and structures a traversable route from its normal entrance to an occupied station, a distinct working area and an exit. Check friendly, rival, newly produced and idle instances where available. Give each of the eight personnel types a visible working and embarking role. Track each catalog ID to its route, job assertion and evidence.
- [ ] 4.4 Add work poses, directional sprites, original low-resolution textures and markings, ambient sound zones, an original score and cues for a machine or bay changing state. Mix music, machinery and radio so the player's crew remains intelligible. Pair critical information with readable text or shape. From the apron, walk below deck and hear the change. From the factory gallery, distinguish a Lintel from a Wake in grayscale. Keep graphics, shaders, sounds and credits in editable folders.
- [ ] 4.5 Replay the 22-metre Mole inside the turning 96-metre Kestrel, both ramp landings, the 44-metre tiltrotor in flight, and the 85-metre tender docking at the 800-metre station. Check occupied seats, solid equipment, eye continuity and local position drift below 2 cm for a stationary passenger over the crossing. Re-run after room unloading and reloading.

## 5. Target the world from desktop, touch and WebXR

- [ ] 5.1 Replace the hard-coded Gate Six XR target with a scene query returning a stable entity, pad, portal, berth, reported contact or walkable ground point. Transform the hit through moving parents. Resolve near surfaces before distant objects, respect occlusion, and recheck ownership, reachability and availability at confirmation.
- [ ] 5.2 Wire mouse pointing, touch selection, chart markers, the XR controller ray and wrist slate to one crew/job/target draft. Preview the recipient and destination, confirm once, cancel, or redirect. Preserve the draft through touch rotation and input changes. In XR keep the controller ray, wrist controls and world actions distinct when they overlap.
- [ ] 5.3 Exercise pointing in **every operation**. Include selecting a pad, escorting a moving Mole, redirecting a ferry, selecting a rail switch and assigning a docking collar. Test an obscured or vanished target, controller tracking loss, two eyes producing one order, ending XR aboard a vehicle, and desktop fallback. Compare the resulting order and target IDs for desktop, touch and XR.

## 6. Integrate the roster, missions and mod packs

- [ ] 6.1 Implement each unit and facility's field-guide role in a real mission or roster exercise with an observable effect, a blocking condition and a player-visible acknowledgment. Work through the faction and facility tables in the design. Include the six faction facilities, the three objectives and all six upgrades. Record what changed in the game world for each ID.
- [ ] 6.2 Convert Gate Six and Tide Window first, then the Compact alternate, Westbound, White Mile, Night Mail and High Water. Bind their win/loss checks to positions, occupants, cargo and completed work. Keep the named opening budgets, the contested 60-second hold, the two paid ferry routes and the eight-alloy standard crossing as regression fixtures.
- [ ] 6.3 Author the choice and adverse outcome in each row of the operation table. Run every operation through its public controls. In the air and orbital operations, confirm a surface job continues and reports while the commander is aboard. Capture a first-person screenshot at the decisive moment in each operation.
- [ ] 6.4 Expose sector layout, interior routes, facility roles, target kinds and mission progression to loose Lua packs. Ship a small pack fixture with a new sector, a crewed asset, an order and a linked operation. Load it alongside Long Watch on native and web using the same binaries as the base game. Test load order, old content, duplicate IDs, missing assets and attribution.

## 7. Save, resume and carry progress between operations

- [ ] 7.1 Define the versioned save payload and serialize at a fixed tick. Include the mission, seed and random state, instance IDs, commander pose and parent, pending orders, queue progress, contacts, cargo, clocks and installed pack versions. Restore an assembled snapshot only after validating its references. Start this work with the identity model from section 1.
- [ ] 7.2 Add Save, Resume, Retry and Continue through the commander's slate or in-world debrief. Write native saves to writable per-user storage and browser saves to IndexedDB. Commit each save atomically, retain the previous valid slot on failure, and give actionable feedback for missing packs, incompatible versions, full storage or an interrupted write.
- [ ] 7.3 Implement the campaign ledger and the transfer rules in the design. Record mission results, surviving crews and hulls, installed upgrades, and eligible handovers. Apply each victory once. Keep standalone starts immediately selectable. Put the Compact operation on a separate faction record and preserve the authored starting challenge for each fresh operation.
- [ ] 7.4 Save aboard the moving crawler with a shore job outstanding and during a Gate Six claim. Quit the process or reload the page, resume, and compare each subsequent checkpoint with uninterrupted play. Test a loss and retry, the same victory submitted twice, an eligible transfer, a foreign asset, an upgraded hull and a standalone replay.

## 8. Verify playability and publish evidence

- [ ] 8.1 Exercise the Gate Six newcomer experience during section 2 and again on the release candidate. Use the installed Game Fun Evaluation workflow to measure the time to first mill order, rejected orders and their reasons, boarding and command from the first tank, wins and retry time. Compare the same seeds before and after a cue change, then use held-out seeds. Check that both openings and the unopposed rival victory still work.
- [ ] 8.2 Profile the expanded port, a multi-unit yard, room transitions and both XR eyes. Record hardware, resolution, frame-time distribution, input latency, web startup, peak memory and dropped frames. Load the active sector on demand, prefetch the next compartment and tune visible geometry or sprite detail where the measurements show stalls. Repeat the same route on software OpenGL, a phone and a physical headset.
- [ ] 8.3 Maintain the independent 95% executable-line gates for first-party C, shipped Lua including packs, and handwritten browser JavaScript. Count otherwise unexecuted sources and target-only adapter code, and keep unit profiles separate from game replays. Run strict OpenSpec and test packaged Windows, Linux, macOS, desktop web, automatic mobile touch and WebXR through the normal entry points.
- [ ] 8.4 Observe a first-time player attempting Gate Six without coaching. Record whether they locate the mill, identify acceptance, delay and completion, find their produced tank, and issue an order while it moves. Record help needed and the player's account of what they saw. Improve the cues and repeat the affected task with a fresh player where an observation reveals a blocker.
- [ ] 8.5 Run the physical-headset protocol in the yard, on a moving vessel and at the station lift. Record headset, browser, refresh rate, posture, perceived scale, wrist text and targeting, discomfort and return to flat play. Keep the two original OpenSpec sign-offs open until their real observations are recorded. [Playtest protocol](../../../docs/playtests/campaign/README.md#two-observations-still-needed)
- [ ] 8.6 Archive the test results, independent coverage counts, scenario inputs, frame captures, playtest findings and any unresolved limitations alongside the build revision. Package loose content with MIT code and CC BY 4.0 original art and audio. Publish updated gameplay screenshots, the roster evidence and instructions for playing, saving and modifying the verified packages.
